# Secrets

Templates sometimes need sensitive values — an API token baked into a config
file, a database URL. Weft's rule is absolute: **secret values are never
persisted**. Not in answer files, not in state, not in sessions, and not in
patches.

## Declaring a secret question

```toml
[[question]]
id = "database_url"
kind = "secret"
source = "env:DATABASE_URL"
prompt = "Database URL"
```

`source` is the secret's **reference** — the only thing weft ever stores:

| Source form  | Resolution at render time                                  |
| ------------ | ---------------------------------------------------------- |
| `env:VAR`    | read environment variable `VAR` (error if unset)           |
| `cmd:...`    | run the command with `sh -c`; trimmed stdout is the value  |
| `prompt`     | interactive hidden prompt; requires a TTY                  |

Examples: `source = "cmd:op read op://vault/db/url"`,
`source = "prompt"`.

## How the guarantee is enforced

This isn't a convention — it's the type system:

- The core value type for a resolved secret **fails serialization with an
  explicit error**. There is no code path that can write it to TOML or JSON.
- `Debug` output redacts it.
- Secrets are **not injected into Starlark**, so no `default`/`when`/`expr`
  can observe, transform, or copy one.
- `weft new` / `weft update` store only the reference string under
  `[secrets]` in `.weft/state.toml`.
- `weft update` re-resolves stored references and **never re-prompts while
  the reference resolves** (a `prompt` source prompts again, by definition).

## Secrets and recording

If a recorded worktree contains a rendered secret value (the base render put
it in a file, or you pasted it), `weft commit` abstracts it
**unconditionally** — you are not asked, because declining would persist the
secret literal inside the patch file. The committed patch contains
`{"answer": "database_url"}`, never the value.

## Restrictions (by design)

- Secret questions cannot be answered via `--answer`, answers files, or
  presets — the reference declared in the manifest (or stored in state) is
  authoritative. `weft check` flags presets that try.
- Expressions cannot reference secret answers.
- A secret can only reach file content through an `{"answer": id}` segment,
  resolved at the final render step.

## CI usage

`env:` sources make CI trivial:

```sh
DATABASE_URL=postgres://… weft new tpl out \
    --answer project_name=svc --non-interactive
```

A missing variable fails with the question id and variable name spelled out.
