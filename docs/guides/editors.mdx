# Editor integration

## JSON Schemas (validation + completion everywhere)

`weft schema` writes JSON Schemas for the two on-disk formats:

```sh
weft schema --out schemas
# schemas/weft-patch.schema.json      → patches/*.json
# schemas/weft-manifest.schema.json   → weft.toml
```

The repo ships generated copies under `schemas/`. Wiring them up gives every
editor validation, completion, and hover docs for template files with no
plugin:

### VSCode — patch files

`.vscode/settings.json` in a template repo:

```json
{
  "json.schemas": [
    {
      "fileMatch": ["patches/*.json"],
      "url": "https://raw.githubusercontent.com/SoheilSalmani/weft/master/schemas/weft-patch.schema.json"
    }
  ]
}
```

### VSCode — weft.toml (Even Better TOML)

```json
{
  "evenBetterToml.schema.associations": {
    "weft\\.toml$": "https://raw.githubusercontent.com/SoheilSalmani/weft/master/schemas/weft-manifest.schema.json"
  }
}
```

### Neovim / anything using taplo

`.taplo.toml` in the template repo:

```toml
[[rule]]
include = ["**/weft.toml"]

[rule.schema]
path = "https://raw.githubusercontent.com/SoheilSalmani/weft/master/schemas/weft-manifest.schema.json"
```

For JSON patch files, jsonls accepts the same `json.schemas`-style
configuration through its `settings.json.schemas` LSP settings.

> The raw.githubusercontent URLs require the repo to be public; until then,
> point at a local checkout's `schemas/` directory instead.

## The language server (`weft lsp`)

One server, every editor: live `weft check` diagnostics published to the
files each issue names, completion for answer ids (inside `{"answer": …}`,
`when`/`default` strings) and dependency names, hover with question/patch
metadata, go-to-definition from an answer reference to its
`[[question]]` (and dep names to patch files), and **inlay hints**: virtual
text next to every `{"answer": …}` / `{"expr": …}` segment (and `default =`
expressions in weft.toml) showing the value it renders to under the
template's example/default answers — `{"answer": "package_name"}` reads as
`⇒ my-demo` inline. The weft.nvim shim enables hints automatically; in
VSCode they follow `editor.inlayHints.enabled`.

### VSCode

Install the extension from `editors/vscode/` (F5 dev-host, or `vsce
package`); it launches `weft lsp` automatically for `weft.toml` and
`patches/*.json`, bundles the patch schema, and adds **Weft: New Project**
— a QuickPick flow generated from `weft describe --json` that ends in
`weft new --answers-json`.

### Neovim

`editors/nvim/` is a small plugin: it attaches `weft lsp` to template
buffers and adds `:WeftNew [template] [dest]`, which opens weft's
full-screen wizard in a floating terminal.

```lua
require("weft").setup({ bin = "weft" })
```

No plugin manager? The raw `vim.lsp.start` call it makes works standalone:

```lua
vim.api.nvim_create_autocmd({ "BufReadPost", "BufNewFile" }, {
  pattern = { "weft.toml", "*/patches/*.json" },
  callback = function(ev)
    vim.lsp.start({ name = "weft", cmd = { "weft", "lsp" } }, { bufnr = ev.buf })
  end,
})
```

## The terminal wizard

Interactive `weft new` / `weft session new` now open a full-screen answers form
(kind-aware editing, live `when`-gating, descriptions and examples inline,
required tracking). It runs in any terminal — including editors' embedded
terminals — so it *is* the TUI story everywhere. `--no-wizard` restores the
sequential prompts.
